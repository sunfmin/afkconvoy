WHEN TO RUN IT

  Never by hand. It is the guard: the check made before each thing a worker of a bound
  repo does, refusing what no worker may do and what its stage may not. Read this to
  learn what a worker is refused, or why one was.

WHO RUNS IT

  Claude Code, as a hook: the fleet adds it to every worker of a bound repo as it
  starts it, whatever the role's repo holds, and Claude Code runs it before each tool
  call the worker makes. A call it refuses is not made.

  pi, through an extension of afkconvoy's own, named on the line that starts a pi
  worker: pi hands it each tool call before making it, it asks this command, and a
  call this command does not allow — one it refuses, and one it could not be asked of
  — is not made. A pi worker whose extension is not there does not start.

  Codex, as a hook too, said on the line that starts a Codex worker and kept in no
  file: Codex runs it before each tool call. Codex makes a call whose hook fails in
  any way but one, so the hook turns every answer but an allowed call into that one:
  a call this command refuses, and one it could not be asked of, is not made.

  A role's own limits are hooks in the role's repo — for pi, extensions there. They
  load because the worker starts there, run beside this one, and refuse in the same way.

WHAT IT READS AND WRITES

  It writes nothing. It reads two things:

  Standard input: one tool call, as Claude Code describes it to a `PreToolUse` hook —
  a JSON object with `tool_name` and `tool_input`. Only a `Bash` call is judged, by the
  words of each simple command of its `tool_input.command`. pi's is described as pi
  describes it to an extension — `toolName` and `input` — and only a `bash` call is
  judged, the same way. Codex describes its own as Claude Code does, and a `Bash` call
  is judged; its `apply_patch` hands the text of a patch as `tool_input.command`, which
  is no shell line and is not judged as one. DSH describes a call with `name` and
  `arguments`: `bash` and `bash_persistent` are judged by `arguments.command`.
  What is refused is decided once, for all.

  The environment: the facts of the worker's stage, which the fleet put there when it
  started the worker — AFKCONVOY_STAGE, AFKCONVOY_WRITES, AFKCONVOY_CONSULT,
  AFKCONVOY_BASE_BRANCH, AFKCONVOY_ESCALATE_LABEL, AFKCONVOY_LOCK_LABEL — and
  AFKCONVOY_HARNESS, the harness that asks: how the call is described is its own.

  Refused for every worker:
    - adding or removing a flow label, a `stage:` label, the escalate label or the lock
      label (`gh issue edit --add-label`, `--remove-label`, `gh issue create --label`,
      and any write of an issue's labels through `gh api`)
    - writing a stage record by hand: only `afkconvoy verdict` writes one
    - writing an intake record by hand: only `afkconvoy intake` writes one, and it is
      what puts a flow label on for a worker
    - merging a PR (`gh pr merge`, or the merge endpoint through `gh api`)
    - pushing the base branch (`git push` with a refspec that lands on it, `--all`,
      `--mirror`)

  Refused besides in a stage its workflow marks `writes: false`, for every consult, and
  for a patrol's worker (AFKCONVOY_PATROL, in place of a stage's facts):
    - committing and pushing (`git commit`, `merge`, `cherry-pick`, `revert`, `am`,
      `push`)

WHAT IT ANSWERS

  Unlike every other command, no JSON: it answers Claude Code the way a hook does.

    exit 0, nothing printed   the call is allowed
    exit 2, a line on stderr  the call is refused; the line is the reason, and Claude
                              Code shows it to the worker — as pi does, given it by
                              the extension, and Codex

  A call it cannot read, an environment that lacks one of the stage's facts, or one
  that names no harness there is, is refused with the reason: nothing is allowed unread.

WHAT TRIPS YOU UP

  - Heredoc bodies and quoted arguments are data, not commands: a report may name
    `rm` or `git worktree remove`, and a read-only `gh` call may search for stage or
    intake records with `--jq` or `--template`. Sending a handwritten record through
    a writing `gh` call is still refused, including through a heredoc. The argument
    after `sh -c` or `bash -c` is executable shell text and is judged as commands.
  - It recognises commands. The same act wrapped in a script, hidden in a variable or
    in a substitution inside quotes gets past it: it stops a worker that errs, not one
    that means to get by.
  - What it misses is checked after the stage: a commit left on the branch by a stage
    marked `writes: false`, or by a consult, is a failure, and the issue escalates; a
    commit or a PR a patrol left is a failed run, reported to a human — see
    `afkconvoy tick --help`.
  - An unbound repo's workers have no guard: their worker launch command is opaque.

  DeepSeek Harness (`dsh`) workers run interactive dsh-tui, with dsh on PATH,
  on a fleet-owned DSH_HOME. The --patch overlay loads the guard
  and orca state plugin; the role's directory, skills, rules, stage model
  and issue's worktree are supplied as described in `afkconvoy run --help`.
