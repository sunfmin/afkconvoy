WHEN TO RUN IT

  Once, as the last command of an inspection: a worker started on a hot worker — one
  whose processes take more than their share of the host — to find out what takes so
  much and why. Its brief ends with the exact line. It found one of three things:

    wrong     the work is wrong: say what is wrong and where
    heavy     the work really is that heavy: say which command is
    not-its   what takes so much is not the worker's: a daemon outside its tree,
              another fleet's gate

WHO RUNS IT

  A worker started as an inspection, in its own worktree: the checkout it was started in
  (`afkconvoy-inspection`). Run anywhere else it is refused.

WHAT IT READS AND WRITES

  It keeps what was found in that checkout's own git dir — a second run says it again,
  and the last one stands — and wakes the `run` of this host (`afkconvoy wake --help`).
  That `run` ends the inspection at its next look, within 30 seconds: it types what was
  found at the hot worker's terminal — not `not-its` — telling it to fix the work, or to
  run the heavy command through `afkconvoy exclusive` from now on; leaves a comment on
  the hot worker's issue saying what was found and why, which is no stage record; and
  removes the inspection's checkout, its terminal with it. The issue stays at its stage,
  and the hot worker keeps working.

WHAT IT ANSWERS

  {"inspected": true, "found", "woke"} — what was found is kept; `woke` is whether a `run`
  on this host was told.

  Errors: the text is empty; the checkout it runs in is no inspection's.

WHAT TRIPS YOU UP

  - An inspection is given 15 minutes. One that has said nothing by then is ended, and
    nothing is typed at the worker; the comment says it found nothing in time.
  - It types nothing itself: the `run` does. An inspection that types at the hot worker
    as well tells it twice.
  - An inspection is held as a consult: it commits, pushes and changes the host never
    (`afkconvoy guard --help`).
