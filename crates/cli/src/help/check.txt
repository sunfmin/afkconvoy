WHEN TO RUN IT

  After every edit to a team's files, a role's skills or a repo's `team` key, and before
  a fleet is started on a bound repo: it says whether the team loads, and if not, every
  fault at once. Edit, run it, and repeat until it exits 0.

WHO RUNS IT

  The operator, or whoever designs the team: in a checkout of a bound repo, or anywhere
  with `--team` or `--dir`.

WHAT IT READS AND WRITES

  It writes nothing. A team is a repo that holds:

      team.md                 the team file
      workflows/<name>.md     one file per workflow; its flow label is `flow:<name>`
      patrols/<name>.md       one file per patrol; a repo runs the ones its `patrols` names

  and of each file only the first ```yaml block is read. The team file:

      escalate_label: ready-for-human    # default
      roles:
        <short name>: owner/repo         # a role is a repo
      precedents: { by: <role>, do: <skill>, max_open: 10 }   # optional; see below

  A workflow file:

      max_rework: 3                      # default
      max_consecutive_rework: 2          # default
      stages:
        - name: <unique; not land, done or human>
          by: <role> | human
          do: <skill>                    # required unless by: human
          model: <model>                 # optional
          writes: false                  # optional; default true
          escalate: { to: <role>, do: <skill> }                  # optional
          on: { pass: <stage> | land | done, reject: <earlier stage> }   # reject optional
      land: { by: <role>, do: <skill> }  # required exactly when a pass leads to land

  A patrol file — its name words of lowercase letters and digits, each starting with a
  letter, joined by `-`, 40 characters at most:

      by: <role>
      do: <skill>
      every: 6h                          # required: a whole number from 1 up, then m, h or d
      model: <model>                     # optional
      max_open: 5                        # required: it is skipped once this many issues
                                         # it opened are open

  `precedents` names who proposes a human's ruling as a precedent: the fleet starts one
  worker in that role, with that skill, for each ruling a human gives an escalated issue
  (`afkconvoy rule`), to open a PR on the team's repo that appends one entry to
  `precedents.md`. `max_open` is required: no proposal is started while that many are
  open there. A team without the key has no precedents proposed (`afkconvoy tick --help`).

  A skill of a role is an entry of `.claude/skills/` in the role's repo.

  Without a flag it reads the config of this checkout for `team`, and that repo from
  GitHub at the head of its default branch — and holds the config's `patrols` against
  the patrols that team has. `--team owner/repo` names the repo instead.
  `--dir <path>` reads a team's files from a directory as they are, committed or not.
  Every role's repo is always read from GitHub, at the head of its default branch:
  through `gh repo clone`, into a temporary directory it removes.

WHAT IT ANSWERS

  {"team", "commit", "files", "escalate_label", "roles", "workflows", "patrols",
  "precedents"} — what it read.
  `commit` is the team's commit read, null with `--dir`; `files` the files read. Each of
  `roles` is {"name", "repo", "commit", "skills"}: `commit` is the one the role's repo
  was read at. Each of `workflows` is {"name", "flow_label", "max_rework",
  "max_consecutive_rework", "stages", "land"}, the defaults filled in; each stage is
  {"name", "by", "do", "model", "writes", "escalate", "pass", "reject"}. Each of
  `patrols` is {"name", "by", "do", "every", "model", "max_open", "runs_here"}: `every`
  in seconds, and `runs_here` whether the config of this checkout names it — false
  with `--team` and `--dir`, which read no config. `precedents` is {"by", "do",
  "max_open"}, or null where the team names nobody to propose them.

  A team with a fault: {"error", "faults"} and exit 1. `faults` holds every fault of the
  team, not the first: each {"file", "key", "problem"}. `key` is a path from the top of
  the file's yaml, counting from 0 — `stages[1].on.reject` — and empty when the fault is
  the file itself. A fault is one of: an unknown key, or one written twice; a wrong
  type; a duplicate stage name; a stage named `land`, `done` or `human`; a `pass` or
  `reject` that names no stage; a `reject` to its own or a later stage; a stage no path
  from the first reaches; a stage whose passes never come to `land` or `done`; a
  `pass: land` with no `land:`, or a `land:` no pass leads to; a role the team file does
  not name; a role whose repo cannot be read; a skill its role's repo does not hold; a
  missing `by`, `do` or `on`; a patrol file whose name is not a patrol's; an `every`
  that is no duration; a missing `every` or `max_open`; and — in the config,
  docs/agents/afkconvoy.md, under `patrols` — a name the team has no patrol for.

  Other errors, as {"error": …}: the repo's config names no team and no flag was given;
  the team's repo cannot be read.

WHAT TRIPS YOU UP

  - From GitHub it reads what is pushed to the default branch. An edit in a checkout
    of the team is checked with `--dir`; a role's is checked only once it is pushed.
  - Following `pass` alone from any stage must end. A loop back is made with `reject`,
    which the breakers count; a round of passes nothing would ever stop.
  - A stage nothing leads to is reported only once every `pass` and `reject` names a
    stage: fix those first and run it again.
