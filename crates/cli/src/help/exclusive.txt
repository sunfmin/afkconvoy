WHEN TO RUN IT

  For work you know to be heavy: a build, a test suite or a benchmark that takes most of
  the host's cores, memory or disk for minutes. You know it from an inspection that
  typed at you that the work really is that heavy, or from your role's rules that name
  the command. Put `afkconvoy exclusive --` in front of that command, every time you
  run it from then on:

    afkconvoy exclusive -- cargo test --workspace

  Not for everyday commands — `git`, a single test, a quick build: the queue makes each
  one wait for every heavy one before it, of every fleet on this host.

WHO RUNS IT

  A worker, in its own worktree. Anyone else on the host may too: the queue is the
  host's, not a fleet's.

WHAT IT READS AND WRITES

  It runs the command once no other `exclusive` command runs on this host — whatever
  its repo, whatever its fleet — and waits in a queue until then: the commands run one
  after the other, in the order they asked. The queue is a directory of the fleet's
  cache (`afkconvoy help cache`), holding one file for each command waiting or running.
  A process that leaves it — its command ended, or it was killed while waiting or
  running — frees its place for the next.

  It writes three lines to the tick log of this host for this repo: as it starts to
  wait, when another command is ahead of it; as its command runs; and as it ends, with
  its exit status. `doctor` and the panel show what runs alone and what waits.

  While it waits or runs, the fleet counts the worker busy, not silent: it is not
  nudged for that. The wait and the run together count toward the gate limit
  (`gate_seconds`), as any background work of a worker's does: one that has been in the
  queue longer than that is silent, and its issue is escalated.

WHAT IT ANSWERS

  Unlike every other command, no JSON of its own: what the command prints is printed,
  and it exits with the command's exit status — 128 and the signal for a command a
  signal ended. While it waits it says so on stderr, in one line beginning
  `[afkconvoy] exclusive:`.

  It exits 127 when the command cannot be started, and 125, with one JSON object
  {"error"} on stdout, when the queue cannot be reached: the command did not run.

WHAT TRIPS YOU UP

  - It may wait long: as long as every heavy command ahead of it runs. Run it as you
    would the gate — in the background, or with a time limit of the gate limit — not
    under a short tool time limit that kills it while it waits.
  - Killing it kills its place in the queue, not only its wait: run it again to wait
    from the end.
  - Only commands run through it wait for one another. A heavy command run without it
    runs beside the one that runs alone.
  - The gate, run by `afkconvoy gate`, does not go through the queue.
