WHEN TO RUN IT

  Hardly ever: `dispatch` claims the issue it starts a worker on. Run it to hold an issue
  back from every fleet — a claim keeps the issue off the frontier — or to repair a
  claim that was released by mistake.

WHO RUNS IT

  The operator, in a checkout of the repo.

WHAT IT READS AND WRITES

  It creates the issue's claim on the remote in one atomic push, which succeeds for
  exactly one instance. Before it, it refreshes the instance's heartbeat when that is
  due. It does not read GitHub: the issue is not checked, and no worker is started.

WHAT IT ANSWERS

  {"won": true, "issue", "ref", "sha", "instance"}
  {"won": false, "issue", "ref", "owner", "detail"} — the issue is claimed already.
  owner is that claim: {number, instance, host, ts, sha}.

  Errors: the push failed and it was not a lost race; the remote cannot be read.

WHAT TRIPS YOU UP

  - `--instance` is required. A lost race is an answer with exit 0: read `won`.
  - A claim the instance holds already answers `won: false`, with itself as the owner.
  - A claim is live only while its instance's heartbeat is within the lease. Under an
    id nothing beats for, another fleet takes it as stale once the lease runs out.
  - Claimed as a running fleet's instance, it is a claim with no worker: that fleet's
    next tick starts a worker on it.
