WHEN TO RUN IT

  Run `afkconvoy kit` at a terminal before starting workers on a new host, or to
  change how this host starts a harness. It needs no repo and changes no remote.

WHAT IT READS AND WRITES

  The host kit is $XDG_CONFIG_HOME/afkconvoy/kit.json, or
  $HOME/.config/afkconvoy/kit.json when XDG_CONFIG_HOME is unset. It is kept on
  this host and never pushed. It is the only source of worker launch commands.

  With no kit it finds every known harness program installed on PATH and proposes
  its stock worker launch command. With a kit it shows the saved commands.
  For each harness, Enter keeps it, a typed command edits or adds it, and - drops
  it. It shows the result and writes only after you answer y or yes. Declining or
  end of input writes nothing. A kit needs a terminal; there is no automatic yes.

WHAT IT ANSWERS

  {path, written, commands}: the file, whether it was written, and each harness's
  command when written. Errors: no terminal; a kit that cannot be read or written.

WHAT TRIPS YOU UP

  `run` asks for this same setup at a terminal when no kit exists. Without a
  terminal it refuses and names `afkconvoy kit`. Other commands never ask.
  A missing harness is refused before workers start; it has no implicit stock
  command. `--worker-command` is gone: edit the host kit with `afkconvoy kit`.
  A command is an opaque shell string; an unbound repo starts it as written,
  under nice with its worktree's TMPDIR. A bound repo adds its role flags.
