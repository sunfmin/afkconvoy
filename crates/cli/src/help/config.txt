WHEN TO RUN IT

  First, before `plan` and `run`: it shows what the fleet goes by in this repo, or why the
  config cannot be read. Run it again after editing the config.

WHO RUNS IT

  The operator, in a checkout of the repo.

WHAT IT READS AND WRITES

  It reads one file — docs/agents/afkconvoy.md of the checkout it is run in, or `--file`
  — and of that file only the first ```yaml block. It writes nothing, and reads neither
  GitHub nor the remote.

THE CONFIG FILE

  A markdown file. The keys of its ```yaml block are the keys of the answer below, named
  and written alike: a file holding every key, each at its default, is

      # afkconvoy config

      ```yaml
      base_branch: "main"                # required: it has no default
      gate_command: ./gate.sh            # required: it has no default
      gate_seconds: 3600
      ready_label: ready-for-agent
      epic_labels: [epic, prd]
      concurrency: 3
      escalate_label: ready-for-human
      lock_label: fleet-lock
      team: acme/team                    # naming a team binds the repo
      patrols: []
      intake_limit: 50
      harness: claude-code
      ```

  A key left out is at the value shown, so the shortest config is the first two lines,
  and a bound repo's those and `team`. The last three are read only beside `team`: an
  unbound repo leaves all four out, and may say one key more, never beside `team`:

      escalate_to: consult               # or human

  What is outside the block is yours to explain it in.
  No command writes this file: write it, commit it, and run `afkconvoy config`.

WHAT IT ANSWERS

  {"base_branch", "gate_command", "gate_seconds", "ready_label", "epic_labels",
   "concurrency", "escalate_label", "lock_label"} — every key, the defaults filled in.
  `gate_seconds` is the gate limit: how many seconds a run of `gate_command` is given,
  by `afkconvoy gate` and by `afkconvoy land --train` alike, before it is ended and is
  red (default 3600). It is written nowhere else: neither command has a flag for it. A
  config that leaves it out is a finding of `afkconvoy doctor`. `lock_label`
  is the label of a fleet lock (default fleet-lock): while an open issue carries it,
  the fleet works lock issues only (`afkconvoy lock --help`).

  A repo whose config names a team is a bound repo, and answers four keys more:
  {"team", "patrols", "intake_limit", "harness"} — the team's directory as owner/repo or
  owner/repo/path (a whole repo, or a subdirectory of one), which
  of its patrols run here, by name (default none; `afkconvoy check` holds them against
  the team's, and `afkconvoy tick --help` says when one runs), how many issues taken in
  by workers may be open (default 50), and the default harness: the one every worker
  runs that its stage or its patrol names none for (default claude-code, Claude Code;
  the others are pi, codex (Codex), and dsh (DeepSeek Harness)). A host where
  `afkconvoy switch` chose a harness
  starts every worker of the repo on that one instead, whatever this key says. A repo that names no team is unbound and answers
  the eight above and one more: {"escalate_to"} — where a hand-off to a human goes first.
  `consult` (the default): the stock consult, afkconvoy's own, is asked first and stands
  where the human would; a human is reached only where it lets the issue through, or
  fails. `human`: every hand-off goes straight to a human, as `afkconvoy help humans`
  says. A bound repo's stages say this each (`afkconvoy help workflows`).

  Errors: the file cannot be read; it has no ```yaml block; `base_branch` or
  `gate_command` is missing; a key is unknown or of the wrong type; `gate_seconds` is
  not a whole number from 1; `team` is neither
  owner/repo nor owner/repo/path; `harness` names no harness; `patrols`, `intake_limit` or `harness` is set
  where no `team` is; `escalate_to` is neither consult nor human, or is set beside `team`
  — the error names the key. Without `--file`, outside a git checkout: "is not in a git checkout".

WHAT TRIPS YOU UP

  - It reads the config only. Whether the team it names loads is `afkconvoy check`.
  - It reads the file as it is in this checkout, committed or not. A worker reads the
    one in its own worktree, which is cut from the base branch: a change is in force only
    once it is on the base branch.

  DeepSeek Harness (`dsh`) workers run interactive dsh-tui, with dsh on PATH,
  on the DSH profile its team or role names: `dsh_profile: fleet` (default)
  or `host-user` (`afkconvoy help team`). The latter loads the host user's
  dsh-tui profile with its plugins, MCP servers, patches, theme and settings.
  Neither edits the user's DSH_HOME; both keep the role's limits.
  The --patch overlay, applied last on either profile, loads the guard
  and orca state plugin; the role's directory, skills, rules, stage model
  and issue's worktree are supplied as described in `afkconvoy run --help`.
