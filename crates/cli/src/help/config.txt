WHEN TO RUN IT

  First, before `plan` and `run`: it shows what the fleet goes by in this repo, or why the
  config cannot be read. Run it again after editing the config.

WHO RUNS IT

  The operator, in a checkout of the repo.

WHAT IT READS AND WRITES

  It reads one file — docs/agents/afkconvoy.md of the checkout it is run in, or `--file`
  — and of that file only the first ```yaml block. It writes nothing, and reads neither
  GitHub nor the remote.

WHAT IT ANSWERS

  {"base_branch", "gate_command", "ready_label", "epic_labels", "concurrency",
   "escalate_label", "lock_label"} — every key, the defaults filled in. `lock_label`
  is the label of a fleet lock (default fleet-lock): while an open issue carries it,
  the fleet works lock issues only (`afkconvoy lock --help`).

  A repo whose config names a team is a bound repo, and answers four keys more:
  {"team", "patrols", "intake_limit", "harness"} — the team's directory as owner/repo or
  owner/repo/path (a whole repo, or a subdirectory of one), which
  of its patrols run here, by name (default none; `afkconvoy check` holds them against
  the team's, and `afkconvoy tick --help` says when one runs), how many issues taken in
  by workers may be open (default 50), and the default harness: the one every worker
  runs that its stage or its patrol names none for (default claude-code, Claude Code;
  the others are pi and codex, Codex). A repo that names no team is unbound and answers
  the seven above only.

  Errors: the file cannot be read; it has no ```yaml block; `base_branch` or
  `gate_command` is missing; a key is unknown or of the wrong type; `team` is neither
  owner/repo nor owner/repo/path; `harness` names no harness; `patrols`, `intake_limit` or `harness` is set
  where no `team` is — the error names the key. Without `--file`, outside a git checkout: "is not in a git checkout".

WHAT TRIPS YOU UP

  - It reads the config only. Whether the team it names loads is `afkconvoy check`.
  - It reads the file as it is in this checkout, committed or not. A worker reads the
    one in its own worktree, which is cut from the base branch: a change is in force only
    once it is on the base branch.
