WHEN TO RUN IT

  To park a claim by hand. A tick does this on its own for a worker that stopped with a
  `blocked` verdict naming open issues the fleet can wait for. Do it yourself when a
  plan keeps showing such a claim under `mine` as `no_pr`.

WHO RUNS IT

  The operator, in a checkout of the repo.

WHAT IT READS AND WRITES

  It reads the worker's latest verdict on the issue and where each issue it names
  stands. On GitHub it records each blocker as a blocked-by edge of the issue and writes
  the status board's last word. On the remote it releases the claim. It removes the
  worktree only when its branch holds no work.

WHAT IT ANSWERS

  {"issue", "action": "parked", "blocked_by", "released": true, "worktree"} — blocked_by
  is the issues it waits on; worktree is "removed" or "kept".
  {"issue", "released": true, "detail"} — no claim is held on the issue: nothing was done.

  Errors, each with nothing changed: the claim is another instance's; "is not parkable"
  — the latest verdict is not `blocked`, or every blocker it named is closed (dispatch
  the issue again instead), or a blocker cannot be waited for (escalate it instead: the
  error says why).

WHAT TRIPS YOU UP

  - `--instance` is required, and must be the instance that holds the claim.
  - It takes no blockers of yours: they are the ones the worker's verdict names.
