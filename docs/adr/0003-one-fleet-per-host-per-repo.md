# A host runs one fleet per repo, and takes its own host's claims at start

afk-fleet takes a dead fleet's claims only after its lease lapses, or when a human runs a takeover and picks the instance. The common death is local — the process was killed, the quota ran out — and the human restarting it on the same machine is the proof. So a fleet instance that starts takes every claim stamped with its own host, unconditionally, whatever the heartbeat says.

That makes "one fleet per host per repo" a rule: a second `afkconvoy run` on the same host and repo takes the first one's claims while it is still alive. Checking that the other process is really dead was considered and rejected in favour of the simpler rule.

## Consequences

- By default there is no drain: plain `stop` is exiting; the claims stay on the remote, the workers keep working, and the next start on this host takes them back and continues them. An orphaned claim is still recovered by continuation, and never released.
- `stop --release` is the drain an operator names. Read while the checkout is still on the list, so the tracker is the one its entry says, it stops the fleet instance and then releases each `claim/<owner>/<tracker>/<n>` it holds on an issue it has not declared on, and each claim on a patrol's run, in one push, each only while it is still that instance's, leased to the sha just read. Each worker is ended after its claim's ref is deleted: its terminal is closed, and its worktree removed only where it is clean at its target; one holding an unpushed commit or an uncommitted change stays, named. The issues keep their labels, an open PR stays open, and an issue still ready is back on the frontier. A cut the instance holds refuses the release, as does a claim that moved since it was read, and a declared verdict or an issue to settle keeps the claim for the next tick: each named, nothing released, and the checkout stays on the list. Only once every claim it held is released does the checkout leave the list, and the instance's heartbeat with it. `--all` takes no `--release`: stopping the host runner keeps the list.
- A heartbeat outlives its fleet instance only while that instance holds claims. A `run` told to stop finishes the step it is in and, holding no claim, removes its heartbeat; holding one, it leaves it with the claims. The start that takes those claims removes the heartbeat they were held under — it is the same proof — and with it this host's other heartbeats that are past the lease and hold nothing. Another host's is no proof of anything here: it is removed only once it is a day old and holds nothing. A heartbeat names its host for this; one stamped before it did is treated as another host's.
- A claim is one whatever it is on: an issue, a patrol's run or a cut. A start takes all three, as well as legacy proposal claims for retirement (ADR-0039). An issue taken is continued; a run taken is ended by the next tick once its worker is gone or has stopped, as any run of the instance's own.
- Another host waits for the lease, or uses the explicit `takeover` command, which is kept for that case only.
